## Why the implementation changed

1. Retrieval initially included unrelated candidate rules in the answer context. A payment answer then mentioned device returns or privacy preparation. Only the leading rule now goes to the answer model for a single-issue question.
2. Some early generated replies promised to submit a recheck request or connect an agent. The demo has no such tools. Its prompt and a heuristic output check now reject known forms of unsupported action claims.
3. A literal citation check incorrectly rejected a valid ID with a space; normalization now accepts it.
4. An unrelated restaurant question produced a valid refusal but was displayed as a citation error. A fixed early scope check now handles obvious unrelated topics.

These changes are targeted responses to observed failures. They are not a guarantee against other failure modes. The cited rule number does not establish whether a sentence is semantically supported by that rule.

## New scenarios, awaiting first online run

The ten questions in holdout_cases.json were prepared after the fixes listed above. Eight specify an expected first rule; H08 and H10 test missing coverage and do not have a correct rule ID. H09 includes a Chinese-number day and an instruction to ignore the rules.

An offline **lexical-only preview** on 2026-09-28 matched the expected first rule in 5/8 known-rule cases.
